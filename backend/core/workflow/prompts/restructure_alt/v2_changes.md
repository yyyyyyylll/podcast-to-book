# Prompt 修改记录 — v2 → v3

## 问题分析

评估反馈指出的最严重问题是【内容完整性不足】和【篇幅不足】，两者根源相同：Prompt未能强制LLM提取并呈现支撑核心概念的“具体操作步骤”和“方法论细节”。当LLM只关注高阶概念时，自然会导致内容空泛、篇幅缩水。这是一个系统性问题，需要通过在核心要素识别阶段增加新类别，并在写作要求中加入强制的“自检与扩充”机制来解决。其他如结构顺序、标题风格等问题属于优化项，可以通过增加提示性规则来改善。

## 修改项（共 5 项）

### 1. [user_template] 在“识别核心要素”中，新增一项要求：识别“可复用的方法论/操作步骤”，并给出了具体示例。

**原因**：直接解决“completeness”得分低的问题。强制LLM从转写中提取具体的、可执行的细节，而不仅仅是抽象概念，从源头上确保了内容的深度和价值。

### 2. [user_template] 在“内容写作要求”之后，新增一个带有警告符号⚠️的【最终质量自检】环节，要求LLM在输出前自查核心板块的篇幅和方法论细节，若不达标则必须返回补充。

**原因**：这是解决“balance”（篇幅不足）问题的最强力手段。它创建了一个自我修正的闭环，将“篇幅”和“深度”的要求从一个静态标准变成了一个动态的、必须执行的动作，能显著提升输出的充实度。

### 3. [user_template] 在“结构设计原则”中，增加了一条关于考虑经典叙事结构（如“问题-分析-解决”）的建议。

**原因**：针对“structure”的反馈，为LLM提供一个行之有效的逻辑“脚手架”，引导其生成更符合读者直觉的叙事流，同时不失灵活性。

### 4. [user_template] 在“内容写作要求”关于标题的部分，增加了“确保所有标题风格统一”的规则。

**原因**：精准修复“title_quality”反馈中指出的标题风格不统一的问题，提升最终产出的专业性和美学一致性。

### 5. [system_prompt] 在System Prompt的核心能力描述中，增加了“深入挖掘并呈现支撑观点的具体方法与细节”的表述。

**原因**：从角色设定的最高层级强化对“细节”和“深度”的重视，使整个生成过程都贯穿这一核心要求。
